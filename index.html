An investigation loop — not a single answer.

H1predicts connection_wait rises first

They disagree → this check separates them. Skip the ones both hypotheses would survive.

Next check = argmax( expected information gain ÷ cost )

Continue while uncertainty remains and a discriminating check exists.

Phase 2 · The problem

A conclusion is not the end.
Acting on it raises a different class of problem.

01
SafetyA wrong diagnosis costs a wasted investigation. A wrong action costs a second outage.
02
Blast radiusRolling back a release is recoverable. Failing over a shared database is not. Nothing in a confidence score tells the agent which is which.
03
Verification“The fix ran” is not “the fix worked”. Without a check, a failed remediation looks like success.
04
ExplainabilityAfterwards, who proves what the agent was permitted to do? Logs can be edited by whoever owns them.
05
AutonomyApprove everything and the value is gone. Approve nothing and it is reckless. Where is the line?

Config and deploy changes are the single largest source of outages. The actions we would be automating are the risky ones.

Phase 2 · Our answer

Five problems. One rule, and five mechanisms.

Stop
when unsure
Prove
it was allowed
Undo
when wrong

Notice what is not on this list: confidence.

A system that acts because it is confident is exactly the system that causes the second outage.

01 SafetyAbstain when evidence cannot separate causes. Refusing is a designed output.
02 Blast radiusActions classified by reversibility and reach. Irreversible ones are forbidden.
03 VerificationRecovery judged only from telemetry collected after the action.
04 ExplainabilityEvery decision sealed. Merkle + Ed25519, verifiable offline by a third party.
05 AutonomyThe line is reversibility, not confidence.
